# 劇情演出 v1

目前所有事件使用 `engine/dialogue_player.gd`。`StoryCore` 保留事件條件、選擇、道具及獎勵規則；演出層只在選擇後的收尾完成時提交一次 `choose`；局部分支會跳到下一節點，只有結尾才提交整個事件的效果。完整規則見 [S4-03 劇情契約](story-contract.md)。沒有 `sequence` 的舊事件仍能以原本的 `text` 播放。

## 編輯劇本

在 `games/demo/events/a2.json` 的 `a2` 事件中加入 `sequence`（新檔需登記於 game.json 的 sources.events）：

```json
{
  "sequence": [
    {
      "id": "opening",
      "speaker": "a",
      "text": "coffee_hello",
      "bgm": "res://games/demo/assets/coffee-ambience-v1.wav"
    },
    {
      "id": "reply",
      "speaker": "player",
      "text": "coffee_reply"
    }
  ]
}
```

每句需要穩定且在該序列內唯一的 `id`、角色 `speaker`、翻譯鍵 `text`。所有語言必須提供翻譯。選項也可加入 `sequence`，作為選擇後的收尾；取消選項直接返回地圖，不執行收尾、不改變狀態。

可選欄位：

| 欄位 | 行為 |
| --- | --- |
| `background` | 該句使用的全畫面背景圖片；省略則顯示變暗的目前地圖。 |
| `portrait` | 該句使用的立繪／表情圖片；省略則使用角色預設肖像。 |
| `bgm` | 更換並循環播放音樂，空字串停止；省略則沿用目前音樂。 |
| `sfx` | 該句開始時播放一次音效。 |

圖片及音訊路徑必須列入 `assets`，且檔案存在。`background`、`portrait` 不會自動沿用到下一句，需要時請逐句指定。角色立繪淡入 0.2 秒。音樂、音效在事件結束時停止。背景／表情替換介面已實作，但目前沒有新增表情素材，也沒有專用 CG；這些不能視為已交付美術。

## 玩家操作與存檔

- 點「下一句」或文字框：先顯示整句，再點一次才前進。
- 自動播放：台詞顯示完後等待 1.4 秒；停在選項等待玩家選擇。
- 已讀快轉：僅略過此次進入前已讀的台詞。第一次看見的句子即使自然顯示完也不會自行跳過。
- 已讀標記包含事件、句 ID、語言及實際翻譯文字；改寫台詞或切換語言後會視為未讀。
- 對話紀錄及隱藏文字框都會暫停前進。紀錄可用滑鼠關閉；隱藏後底部控制列仍保留。
- 已讀狀態存在玩家 profile，不隨遊戲存檔回退。對話紀錄目前只保留本次執行期間的內容，開始新遊戲會清空。
- 演出途中尚不支援存檔。正常結束時先提交事件，再寫自動存檔；手動存檔不會被覆蓋。

## 試玩與驗證

晴的第二個事件 `a2` 已提供「三句開場 → 選擇 → 兩句收尾 → 返回地圖／自動存檔」範例。正常遊玩：先認識晴、買咖啡，等到傍晚再找她。這是短篇功能示範，尚非五分鐘的完整正式劇情。

執行 `python tools/dev.py check`：

- pytest 靜態驗證漏檔、翻譯、重複句 ID 及其他原有內容條件。
- Godot 演出測試比較手動、自動與快轉的結果，驗證未讀保護、暫停、取消、延後提交、重複提交及自動存檔。
- 真正滑鼠事件從開局走完兩位角色的六個事件，包含對話紀錄、隱藏／恢復、購物及存讀檔。

演出測試使用明確狀態 fixture 隔離播放功能；全流程測試仍透過正常移動、互動與滑鼠操作推進。這些案例不等於證明任意新增劇本一定不存在死路。

待後續：正式 CG／表情素材、影片及 Live2D、任意劇本可達性探索，以及演出中存讀檔。
