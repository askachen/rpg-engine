## 第一批：P0 匯入基礎

### S5-01 通用能力值／數值變數

- 建立有 stable ID 的數值定義；INT／FIT／CHA 是遊戲內容，不是引擎固定欄位。可顯示的能力與內部變數共用數值規則，顯示名稱使用語系鍵，布林 flags 維持既有責任。
- 定義整數／有限數值型別、預設 0、可配置初值及可選上下限。若範圍排除 0，必須給合法初值。實作前固定超界的拒絕／截斷政策，Schema、Godot、UI 與測試一致；不接受 NaN／Infinity 或隱式字串轉數字。
- 提供數值增減、必要設定效果及明確比較運算 eq/ne/lt/lte/gt/gte；未知 ID、型別／範圍錯誤須含來源路徑。效果依既有事件交易一次提交，失敗不得部分扣款或增加能力。
- 玩家狀態面板與開發者檢視能看到值；新欄位可存讀檔，舊內容未定義時行為不變。舊存檔缺新欄位依定義初始化；已存在但非法的值不得靜默改成 0。完整版本遷移政策仍在 S6-01。
- 正反例：訓練 INT 0→1、不足門檻拒絕、等於門檻通過、取消不增加、非法效果不部分提交、跨遊戲存檔不串值。

### S5-02 日期比較

- 使用從 1 起算的絕對 `state.day`，支援通用比較；不是把日期寫入旗標。與時段条件可 AND 組合。
- 事件、NPC 排程、可用提示與開發診斷共用同一條件評估。測試最小日之前／當日／之後、深夜跨日與存讀檔。
- Extra Day 僅為 S5-09 顯示策略；Day >= 30 等規則永遠比較絕對日期。

### S5-03 地點與入口上下文

- 引入事件判定上下文：目前 map、玩家位置、互動 target ID、可選具名 zone。具名區域與邊界須有明確資料定義，不能依 UI 標題推算。
- 最低必要能力為 map＋target；同批提供 zone 的 ID／範圍引用與判定，供探索使用。區域預設依玩家所在格判定，與 NPC 位置分開；重疊區域可同時匹配，邊界包含規則須固定。
- `event_candidates`、條件提示與真正事件啟動使用同一判定。點擊前狀態或 NPC 位置變化時重新驗證；缺 target／zone 上下文的自動入口不得視為符合。
- 正反例：同角色室內與室外只選各自事件；同地圖不同物件不可串觸發；區域邊界、無效引用、優先度競爭及舊無位置限制事件相容。

### S5-04 新局、物件與探索事件入口

- 抽出共用事件啟動流程，供 NPC、物件與探索入口呼叫；事件不必有 character，仍可透過 sequence 的 speaker 演出。區分事件歸屬與啟動來源。
- `opening_event` 在使用者真正建立新局後、開放地圖操作前播放。內容載入／validate／讀檔不自動播放；成功／取消／失敗策略明確，不可重入或重複提交。
- inspect／指定物品等入口可指向完整事件，保留舊立即提示行為；完整入口沿用完成紀錄、局部分支、repeatable、time_cost。消耗物品與事件效果的提交／取消須一致，不可啟動先扣一次、結束再扣一次。
- 探索先提供明確的玩家互動入口；工作、訓練及「沒有收穫」均能以事件結束後耗一時段表達。任意每幀自動事件掃描、隨機掉落系統不隱含納入此任務。
- 自動入口本批至少包含 opening；headless 測試可觀察／完成同一開場事件。若遊戲需要進區域即自動觸發，另在本項實作前列明觸發時機、防重入與再次進入政策。
- 驗收：新局開場一次、讀檔不重播、沒有 NPC 也能工作／訓練、空探索耗時、缺物品拒絕、連點／取消／中斷效果恰好提交一次。

## 第二批：P1 完整玩法

### S5-05 條件樹與行動紀錄

- 保留現有條件陣列的 AND 語意，新增巢狀 all／any。Schema 拒絕空群組／未知節點，設定合理最大深度；診斷回傳完整條件樹，不能只回傳「未達成」。
- 成功提交一次事件可記錄一筆具穩定標籤、事件 ID、絕對日／時段的行動；取消、拒絕、讀檔與回想不能新增。多標籤同一行動在 work OR train 的聯集計數只算一次。
- 提供持久累計與明確窗口的計數查詢，至少能表達 `RecentWorkTrainCount >= 7 OR Day >= 30`，保留原事件 stable ID。紀錄保存／壓縮策略須支援宣告的最大窗口，不能截斷後仍聲稱計數精確。
- **Recent 待定義**：由內容團隊決定最近 N 個日曆日、N 個時段或自某里程碑以來，以及是否含當日／當時段。不得自行當成「七天」。先做累計與條件樹不受此決策阻擋；窗口案例在定義確定後才可驗收。
- 測試 OR 各分支單獨成立／均不成立、AND 嵌套、窗口邊界、跨日／多標籤去重、存讀檔後計數相同。

### S5-06 提示與進度解耦

- NPC／物件的 ! 使用當前上下文候選；與真正可觸發事件一致。沒有可用事件時不顯示 !，避免固定「···」掩蓋可用性。
- 非線性追蹤清單只決定顯示，不限制觸發順序；舊 routes 的強制線性語意保留，以明確模式／另設追蹤定義擴充。多位角色可各自推進。
- 側欄／狀態頁可顯示數值門檻、日期、地點、完成事件、AND／OR 與計數。是否顯示未解鎖事件名稱／細節由內容設定，開發模式可看完整原因。
- 對照條件不足→滿足、換圖、跨時段、購物、完成事件和讀檔後即時刷新；繁中／英文及滑鼠操作實測。

### S5-07 庫存政策

- 以明確 unlimited 模式表示永久可買；不使用超大數字或負庫存哨兵。扣錢、加物品及前置條件仍走原交易流程，UI 顯示無限庫存的翻譯文字。
- 有限庫存相容；補貨可由明確效果執行，或配置「跨日補到上限」等固定規則。定義 add 與 set 的差異、上限、觸發時間和 last-restock 記錄；同日讀檔／刷新不再補一次。
- 測試多次購買、缺錢／遠離拒絕、售罄有限商品、跨日補貨、跳過多時段、讀檔後庫存一致。

### S5-08 完整事件回想

- 畫廊條目可連結已解鎖事件，完整播放對話、分支與媒體；未解鎖無法啟動。已解鎖回想跳過事件及選項的玩法門檻，但保留分支結構與內容引用檢查。
- 使用隔離的回想狀態／執行模式，禁止真實狀態提交与持久化；不能只在結束時還原金錢。需要的分支局部變數可在隔離空間運作。
- 錢、道具、數值、日期、旗標、完成紀錄、行動計數、stock、位置、gallery 解鎖、已讀 profile 及存檔皆不得被回想改寫。禁止回想內普通存檔／開場／世界事件重入。
- 結束、取消、例外、影片跳過均回到畫廊並清理聲音／圖層；使用前後狀態與持久檔案比對，不只驗證畫面。預設列 P1，未取得縮減範圍決策前不降為媒體重播。

### S5-09 日期顯示

- 配置正常日數界線與語系格式；Homestay 可設 90，Day 90→Day 90，91→Extra Day 1，92→Extra Day 2。
- HUD、存檔槽位摘要、玩家可見日期提示共用 formatter。開發診斷仍能看到絕對日；核心条件、窗口、排程與存檔保存絕對值。
- 延住事件由內容製作，本項不硬編碼 Day 91 的劇情；測試不同界線、未配置時的舊顯示，以及跨界存讀檔。

## 第三批：P2 依需求選配

- **S5-10**：用穩定圖層 ID 與 keep／replace／clear 管理跨句畫面；keep 保留動畫時鐘，不重新載入；新事件、取消、回想切換時清理。以兩句連續循環動畫的幀／時間及實際渲染驗證。若 Homestay 只使用靜態 CG，先延後此項。
- **S5-11**：明確 auto-complete 事件可無選項；最後一句確認或自動閱讀結束後提交一次，空序列亦有確定行為。舊非空 choices 保留；未宣告 auto-complete 的缺選項事件仍報錯。若暫用單一「繼續」，不宣稱支援自動結束。
- 開發前由遊戲演出與 UX 決定是否必要；即使延期，也須在移往 S6 時記錄未交付能力與原因。

## S5-12 整合驗收與每批交付

分成 12A 與 12B 兩個門檻，不要求先完成全部 P1 才開始驗證 P0：

1. **12A（S5-01～04 後）**：獨立通用 fixture，新局開場→在指定位置工作／訓練→能力達標→跨過最小日→與正確位置 NPC 觸發事件；加入錯地點／錯 target／缺能力／提前日期／取消的負例。以普通遊戲操作推進，不注入狀態冒充通關。
2. **12B（S5-05～09 後）**：加上工作／訓練計數 OR 日期的兩條路、非線性追蹤、無限購買與補貨、無副作用回想、Extra Day，並交錯存讀檔。需要的日數可用合法等待操作推進。
3. Schema／語意診斷、CLI headless、既有 demo／fog_harbor／first_story 回歸，加上可視功能的原生滑鼠及渲染驗收。測試輸出包含事件 ID、上下文、失敗條件樹與狀態差異。
4. 文件與新遊戲範例示範真實可用 JSON；未完成能力不得出現在「已支援」清單。每個交付批次更新 README、TASKS、驗收紀錄並 commit／push，使用者確認後才標已確認。
5. 真正 Homestay 資料提供後再做匯入檢查、指定首月路線與資源／事件可達性案例；本 repo 的合成 fixture 不代替該團隊內容驗收。對所有選項均可通關的探索與界線仍由 S6-04／05 負責。

目前不需要為此規劃阻塞其他工作。窗口定義、探索是否需要自動進區觸發、跨句動畫與無按鈕結尾需求，分別在相關任務開發前確認；不因尚未決定這些項目延誤 S5-01。
