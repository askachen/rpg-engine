# 地圖視窗、鏡頭與轉場

S4-01 本批完成鏡頭、滑鼠提示、地面裝飾分層及出入口轉場。四方向面向與逐格行走動畫仍是下一批，不能以既有角色上下浮動代替。

## 鏡頭與輸入

地圖在 1920×1080 設計座標中的 (60,180) 起，使用 1320×760 的裁切視窗；HUD、背包、對話與選單不隨鏡頭移動。小地圖維持原本位置，大地圖以玩家為中心並夾住地圖邊界。鏡頭目前逐格跟隨，沒有額外平滑插值。

main 的 update_camera、cell_to_screen、screen_to_cell 統一鏡頭與滑鼠座標。世界用獨立 world_surface Control 繪製，放在 clip_contents 視窗下；surface 必須有足以覆蓋整張地圖的尺寸，否則離開原點後會被 Godot 裁掉。地板只繪製視窗內格子，其他物件由視窗裁切。

只有地圖視窗範圍內的點擊會開始尋路。滑鼠停在互動格上會顯示外框及該物件 label；條件不符顯示 unavailable。已拾取物件不提示；選單、對話或轉場時不提示。使用既有語系鍵，不需要新增硬編碼翻譯。

## 地毯與碰撞

furniture 的既有 `layer: "floor"` 現在會在牆壁、人物及一般家具前繪製；省略 layer 維持 prop 深度排序。`solid` 仍獨立控制碰撞：地毯應指定 `solid: false`，不是看見 layer 就自動忽略碰撞。

驗證器現在與正式規則一致，不讓非 solid 裝飾占用碰撞集合；可放在人物出生點或桌椅底下。solid 家具重疊與阻擋出生點仍會報錯。霧港工坊恢復大片地毯的重疊配置，已以實際畫面確認桌子和商店標籤仍可見。

## 換圖契約

到達符合條件且相鄰的出口時，先淡出 0.18 秒，黑畫面時呼叫同一 core.act 切換地圖，再淡入 0.18 秒。整段期間鎖定滑鼠、鍵盤及 HUD，清空待走路徑，目的地重新計算鏡頭。失敗條件仍由正式規則判斷，未解鎖出口不進入成功換圖流程。

main.execute 對出入口是非同步入口；呼叫端若要等待視覺完成，應等待 transitioning 回到 false。headless 規則橋接 core.act 仍立即執行，不依賴動畫時間。world renderer 不修改玩法狀態。

## 測試

`python -m pytest tests/test_camera.py -q` 會建立 60×32 格 fixture，實際送出螢幕點擊跨越地圖，驗證雙軸鏡頭、座標反算、hover、換圖淡出／淡入輸入鎖定、目的地鏡頭歸零及操作恢復。另驗證地毯和 solid 家具的重疊規則。

實際 GPU 測試另外截取遠端角落並檢查像素不是背景色，避免只有 headless 規則通過而地圖沒畫出的假成功。此 fixture 是技術測試，不是正式關卡或新增故事內容。
