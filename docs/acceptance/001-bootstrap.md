## 實際驗證

- 專案預設入口仍能啟動原遊戲；命令列 `--game=...` 可選取另一個內容檔。
- 測試使用 ID 為 `alternate_game` 的 fixture 啟動真正 UI，保存設定、已讀、解鎖與進度，重新建立 UI 後正確讀回。
- 另一個 game_id 的存檔槽不被覆蓋；讀取不同遊戲的存檔被拒絕，profile 路徑不同。
- 實際寫入舊 demo profile，再啟動 UI，語言、已讀與解鎖皆保留。
- 空 ID、路徑穿越／分隔符與過長 ID 被拒絕；不存在的入口回報載入失敗。
- 原滑鼠通關、演出控制與存讀檔測試繼續通過。

測試環境：Windows、Godot 4.7.2、Python 3.13；測試存檔使用暫存 APPDATA。報告由 `test-results/junit.xml` 產生，下次執行會更新。
