# 背包、商店與基本選單（S4-09）

## 背包

地圖底部或遊戲選單可開啟背包，显示數量大於零的物品。名稱取自 items[id].name，說明取自可選的 description，兩者皆為語系鍵；未提供說明時顯示通用文字。空背包有明確提示。

```json
{"locker_key": {"name": "locker_key", "description": "locker_key_description"}}
```

目前地圖中，有可見且未完成的 inspect 物件要求此物品時，顯示使用按鈕、所需數量與是否消耗。未靠近或數量不足時禁用並顯示原因。點擊後走既有 core.act interact 規則，核心重新檢查距離／條件／數量並交易式套用效果。沒有對應物件時提示在劇情或互動物件中使用。

這不是任意物品效果腳本：一般劇情道具仍由事件消耗，不支援自由贈送、裝備、販售、丟棄或在背包直接跳過任務。霧港鑰匙可由背包開啟舊置物櫃，依既有設定消耗一把；其他三件物品有對應說明。

## 商店

商店顯示金錢、商品名稱／說明、持有量、剩餘庫存與單件價格。缺錢或售罄時按鈕停用，旁邊顯示原因。一次購買一件，完成後返回地圖；再次開店顯示更新的數量與金額。

`core.shop_offer(shop_id,item_id)` 是唯讀查詢，回傳 available、reason、price、stock、owned。核心 buy 與 UI 使用同一判斷；即使直接送入過期請求，仍重新驗證商店是否可達、商品、庫存、金錢。失敗不扣錢或增減物品。庫存沿用單局 state.stock 與既有存讀檔，不增加新經濟規則。

## 進度、離開與名單

每位角色進度上方有 ＋／− 按鈕；收合不變動角色狀態，切圖仍保持，重啟恢復展開。完整進度與條件可隨時再展開。

開頭／遊戲選單提供製作名單。內容包可在 game.json 根層設定 `credits` 字串陣列，各項是語系鍵，例如 `["credit_project", "credit_engine", "credit_art"]`。未配置時顯示尚未提供。範例列出專案、Godot 與 AI 示範美術，正式團隊人名與授權清單仍由作者維護，S7 授權交付不因此完成。

離開按鈕與系統視窗關閉請求都顯示確認，提醒未存進度會失去。否則返回目前畫面；確認後才結束程序，不自動覆寫手動存檔。對話中收到關閉請求會暫停對話與影片，取消時恢復先前暫停狀態。返回標題仍沿用既有確認流程。

## 測試

`tests/menus_flow.gd` 以滑鼠跑拾取鑰匙、背包使用、往返工坊、拾取津貼及購買；驗證空背包、收合、缺錢、扣款／數量／庫存、取消離開及名單。售罄情境以獨立 fixture 設定庫存，另驗證 UI 與直接 core 請求皆拒絕且狀態不變。另一程序真正按離開確認並檢查正常退出；原生關窗訊號另有測試。

完整解析度／長文／大量物品排列仍由 S6 與內容驗收補齊。此批不新增背包分頁、物品圖示或批量購買。
