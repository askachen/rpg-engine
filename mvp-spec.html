01 ／ 產品定位

目標使用者是以 AI Agentic Coding 開發遊戲的創作者。成品遊戲包含一位男主角、多位女主角、可行走地圖、選項對話、條件式劇情與多媒體演出，目標發行平台為 Steam 上的 Windows 遊戲。

參考截圖的三種呈現：① 俯視角地圖探索；② 地圖上疊加立繪與對話；③ 背景圖、立繪或全畫面 CG 的劇情演出。截圖內的台詞、人物名稱與任務內容不構成需求。

探索地圖→互動／選擇→檢查條件→播放劇情→更新狀態→解鎖後續事件
成功標準：完成一款可從頭玩到尾的示範遊戲，並以第二個小型內容包證明新增遊戲不需要修改共用引擎。

03 ／ 地圖、互動與時間

地圖與移動

  • 四方向格子移動、障礙碰撞、鏡頭跟隨、面向互動。完整流程必須可只用滑鼠操作：左鍵點地尋路、點 NPC／物件自動走近互動，右鍵停止；等待、選單、對話、購買及存讀檔均有可點擊入口。鍵盤為選用操作。提供滑鼠跑步切換按鈕，預設開啟，約為步行 2.4 倍速度；也可按住 Shift 暫時跑步，仍遵守逐格碰撞。
  • 地圖包含圖層、碰撞、NPC、物件、出口與具名出生點，全部可由文字資料定義。一般示範地圖為 24×14 格；住處採 30×17 格三房兩廳，另含廚房、浴室與中央走道。家具以獨立資料配置占地碰撞，美術維持原始長寬比。視覺基準包含織紋地毯、窗簾、壁畫、植栽、三位角色的地圖 avatar／頭像與對話肖像，並統一室內外素材及介面風格。
  • 出口支援進入條件、目標地圖與出生點；轉場淡入淡出，鎖定重複操作。
  • NPC 支援依時段、旗標與劇情階段決定出現位置，以及可互動提示。
  • 物件支援調查、拾取、啟動、使用道具；持久狀態以唯一 ID 保存。

時間規則

白天→晚上→深夜→次日白天

保存遊戲日數與時段。預設只有等待、休息及指定事件耗時；走路、查看介面、閱讀文字不耗時。事件資料定義推進幾個時段，跨過深夜增加一天。時間變更在事件安全結束點生效，重新計算 NPC 配置與營業狀態。

經濟與物品

單一整數貨幣、可堆疊物品、固定價格與庫存；支援取得、消耗、購買及不足提示。購買是不可分割操作：金錢、庫存與背包要一起成功或完全不變。關鍵道具預設不可販賣、不可任意消耗；必要時段事件可再次遇到，避免無意造成永久卡關。

04 ／ 角色進度與劇情執行

每位女主角維護獨立階段、好感度與已完成事件。多位女主角可同時推進；MVP 不做選定一人即封鎖其他路線。選項可修改狀態或進入局部分支，再回到該角色主線。

事件契約

欄位用途
穩定 ID／觸發方式指定 NPC、物件、區域或明確入口。
推進條件AND 組合：好感度、角色階段、已完成事件、旗標、金錢與物品數量。
觸發情境所在地圖、日期／時段；與角色的互動方式。
演出與選項文字 ID、角色、表情、背景、音樂、動畫、影片與局部分支。
完成效果物品／貨幣變更、旗標、好感度、事件完成、角色升階、時間推進。
執行規則一次性或可重複、優先順序、耗時與結束行為。
達成條件只解鎖事件；完成事件才升階。同一 NPC 多個事件可用時按明確優先順序選擇，平手依穩定 ID 排序並給開發警告，無事件時使用日常對話。

玩家可見的進度

角色 A｜目前階段：熟悉
下一階段：邀約
✓ 好感度至少 20：目前 25
✓ 已完成「初次見面」
✗ 持有「邀請函」：目前 0 / 1
觸發提示：條件達成後，晚上到咖啡店找她。

玩家介面與開發者工具共用同一套條件評估，輸出「需求／目前值／是否通過」。AND 為必要能力，OR 可預留結構但不列為 MVP 驗收。一般劇情資料不執行任意程式碼。

中斷與重複執行

演出期間鎖定地圖操作。已讀快進或跳過媒體必須走同一完成流程；返回標題與讀檔需清理演出資源。一次性完成效果不得重複套用。MVP 存檔限定事件外，異常終止後回到最近完整存檔，不恢復半段事件。

05 ／ 基本畫面與操作

畫面MVP 要求
標題選單新遊戲、繼續、讀檔、畫廊、設定、製作名單、離開。無有效存檔時停用繼續；繼續載入最新有效存檔。
探索 HUD地點、日數／時段、金錢、互動提示與選單入口；角色進度可收合。
遊戲內選單返回、角色進度、背包、存讀檔、設定、返回標題、離開。
對話姓名、表情立繪、逐字顯示、條件選項、對話紀錄、自動播放、已讀快進、隱藏對話框。
設定語言、視窗／全螢幕、解析度、文字大小與速度、自動播放速度、主音量／音樂／音效／語音音量。
存讀檔6 個手動槽與 1 個獨立自動槽；地點、日數／時段、存檔時間；覆寫／刪除確認、損壞檔案提示。
背包／商店名稱、描述、數量、可用操作；價格、庫存、持有金錢與不足原因。
畫廊CG／影片縮圖與分類、鎖定佔位、放大欣賞、播放／返回；不改動遊戲狀態。
確認與提示取得物品、購買失敗、存檔結果；離開未保存進度時確認。
製作名單作者、素材來源與授權資訊，由內容資料提供。

選單必須可使用滑鼠選取、確認及返回，並保留鍵盤操作；開關選單後正確恢復焦點，不讓同一次按鍵同時觸發對話和地圖互動。標題背景、Logo、配色、字型與畫廊分類可依遊戲配置。

06 ／ 圖片、動畫、影片與 Live2D

媒體MVP 行為交付界線
圖片／立繪背景、CG、表情切換、位置縮放、淡入淡出。必要
簡單動畫立繪移動、逐格／循環動畫；定義完成或停止時機。必要
影片單次／循環、跳過、音量、比例維持、播放完成返回事件；循環片段必須有明確退出方式。必要；執行格式先用 .ogv
音訊BGM、音效、可選台詞語音；切換與音量分組。必要；示範不要求全語音
Live2D先驗證單模型透明疊加、待機、表情／動作、顯示隱藏、Windows 打包。前期技術驗證；通過後納入基本支援

角色演出使用語意指令，例如「表情＝微笑、動作＝點頭」，由角色素材設定映射到圖片或 Live2D 資源。Live2D 即時模型需要專用執行與繪製整合；事先輸出的 Live2D 影片則走一般影片流程。

MP4 是可接受的原始素材方向，不等於已支援直接播放。原生播放器方案先轉為 Ogg Theora；轉檔需檢查成功、時長與可解碼性。大量或長影片須先驗證目標硬體效能。Live2D 嘴型同步、追視與部位互動暫緩。

07 ／ 狀態、存檔與解鎖

資料範圍內容生命週期
單局存檔地圖、主角位置／朝向、日期時段、貨幣、背包、角色階段／好感、旗標、完成事件、物件狀態、商店庫存。新遊戲重置；讀檔還原。
跨存檔紀錄已讀文字 ID、CG／影片解鎖。讀舊檔或新遊戲不撤銷；不同遊戲隔離。
使用者設定語言、視窗與顯示、音量、文字設定。重新啟動後保留；不同遊戲隔離。
  • 存檔包含 game_id、資料格式版本、內容版本；使用可寫的使用者資料目錄。
  • 先寫暫存檔再替換，保留必要復原能力，避免寫入中斷毀掉唯一存檔。
  • 不相容版本顯示明確錯誤；MVP 提供版本檢查與遷移入口，不承諾任意未來版本自動相容。
  • 自動存檔在事件效果完成且狀態一致後執行；畫廊播放不改變單局狀態。
  • 回標題再開新局時重建遊戲狀態，避免上局的節點、訊號或旗標殘留。

08 ／ 架構、資料與 AI 工作流程

Godot 4.x 穩定版＋GDScript 為建議技術基準；開始實作時鎖定確切引擎、匯出範本與依賴版本。規則層與畫面層分離，正式遊戲和 headless 測試執行同一份規則。

模組責任
Content Registry載入與驗證角色、事件、地圖、道具、素材和文字 ID。
Game State／Rules狀態、條件評估、原子效果、時間與角色進度。
Story Runner對話、選項、演出命令、事件生命週期。
World／Presentation地圖、移動、互動、UI、媒體與輸入鎖定。
Persistence存檔、全域解鎖、設定、版本檢查。
Tooling／Test Bridge內容驗證、狀態診斷、可控操作、測試報告與打包。

建議內容組織

engine/                 共用執行模組與場景
games/demo/
  game.json             遊戲 ID、主題、起始狀態、入口
  maps/                 圖層、碰撞、NPC、物件與出口
  characters/           角色、階段、表情與動作映射
  events/               觸發、条件、演出、效果
  items/                物品與商店定義
  gallery/              CG／影片項目與解鎖規則
  locales/              文字 ID 與各語言內容
  assets/               圖片、音訊、影片、模型
schemas/                資料格式契約
tools/                  驗證與建置入口
tests/                  規則情境、通關路線、整合測試

以上是邏輯分工草案，實際打包目錄可調整；所有必要內容必須包含在匯出產物中。

  • JSON 配合 Schema、欄位說明、合法範例；每個事件拆成小檔，ID 穩定且唯一。
  • 地圖用圖塊代號與座標描述，工具生成可載入地圖；編輯器僅作預覽或除錯。
  • 各遊戲使用固定版本共用引擎，主動升級；遊戲內容不得硬寫進共用模組。
  • AI 流程：改資料 → 格式／引用驗證 → 規則與通關測試 → 視覺檢查 → Windows 打包。

09 ／ 多語言、解析度與 Windows

玩家可見文字全部使用穩定 ID：台詞、姓名、選項、道具、條件提示、UI 及錯誤訊息。繁中與英文作為 MVP 驗證語言，定義備援語言、字型與缺譯政策。修改譯文不改事件與文字 ID；已讀判定另外包含語言及實際譯文，改寫或切換語言後視為未讀。替代參數在不同語言間需一致。

以 1920×1080、16:9 為設計基準與預設視窗解析度；驗證 1280×720、1920×1080、2560×1440、3840×2160，以及 16:10／21:9 留邊。人物和影片維持比例；像素地圖與高解析 UI／立繪分別處理縮放。長譯文與放大字體不可遮住必要按鈕。

Windows 匯出需能獨立啟動、寫入存檔、播放媒體；驗證非 ASCII 路徑與一般使用者權限。Steam 是目標發行通路；本階段交付可發行基礎建置，不包含商店送審、上傳、成就或雲端存檔整合。

10 ／ 開發者模式

  • 查看與修改角色階段、好感、旗標、完成事件、金錢、背包、日期時段。
  • 查看 NPC 配置、地圖物件狀態、候選事件及其優先順序。
  • 逐條說明事件條件的目前值、需求值與失敗原因。
  • 傳送到具名出生點、載入測試狀態、指定播放事件。
  • 輸出帶來源事件與步驟的狀態變更紀錄，提供機器可讀 JSON 診斷。
  • 開發操作明確標记，正式通關測試禁用；發行版本停用開發者入口。
除錯目標不只是看見數值，而是能直接回答：「為什麼下一個事件沒有出現？」

11 ／ 自動化測試規格

pytest 負責調度與報告，Godot headless 執行正式規則。 Python 不重寫遊戲規則。測試橋接提供操作、回應、狀態快照與失敗原因；固定亂數種子、可控制遊戲時間，限制步數與執行時間。

層級檢查項目驗收要求
T1 靜態內容Schema、重複 ID、懸空引用、缺素材、缺譯／參數不符、出生點、出口、事件依賴無入口循環。缺陷含檔案位置與 ID；錯誤使指令非零退出；不得把靜態檢查宣稱為完整可達性證明。
T2 規則AND、門檻上下界、時間循環、原子購買、消耗、一次性事件、角色互不干擾、存讀檔。同一输入得到可重現結果；針對邊界和失敗情境測試。
T3 通關新遊戲到各女主角結局；交錯推進所有角色；存讀檔後繼續；純滑鼠輸入完成同一流程。只用正常可達操作；不得加錢、傳送穿牆、注入物品或直接標記事件完成。
T4 整合地圖／UI、選項、媒體解碼、播放結束與跳過、設定、畫廊、Windows 匯出啟動。有圖形／音訊環境的測試單獨執行；不以 headless 通過代替實際呈現驗證。

通關路線範例

新遊戲 → 正常移動並拾取零用錢 → 經出口到商店
→ 購買咖啡 → 等待晚上 → 到咖啡店與角色 A 互動
→ 選擇送禮 → 驗證道具扣除、事件完成與階段推進
→ 存檔／載入 → 完成後續事件 → 驗證結局

劇情測試可加速文字與媒體等待，但必須走相同完成回呼與效果；實際媒體解碼另測。自動移動可使用測試導航輔助，但必須遵守碰撞、出口與正常移動規則。

防卡關情境

  • 好感門檻差一點／剛好達成；多個 AND 子條件只有一項未滿足。
  • 金錢花完、道具不足或已消耗、商店庫存不足。
  • 錯過時段後再次等待是否能完成；關鍵資源是否仍有取得途徑。
  • 多女主角交錯順序、共享資源競爭、換圖與存讀檔。
  • 連按、重複互動或媒體跳過是否造成重複獎勵／扣款。
通過指定路線只證明那些路線可完成，不能保證所有選擇排列都不卡關。MVP 必須附路線與情境覆蓋清單；更全面的有界狀態探索列為後續擴充。

基本介面回歸

無存檔的繼續按鈕、新遊戲狀態重置、最新有效存檔選擇、設定重啟保留、畫廊解鎖跨存檔保留、畫廊播放不變更金錢／物品／劇情、返回標題的輸入與資源清理。

報告與執行入口

提供單一快速檢查入口與完整測試入口。失敗輸出測試名稱、重現操作、種子、前後狀態、目標事件和阻擋條件；超時不得標記成功。目標為小型示範快速檢查約一分鐘內，實際門檻以開發環境量測後鎖定。

12 ／ 開發里程碑與完成定義

階段交付通過條件
M0 契約與風險驗證固定技術版本、Schema 草案、測試入口；影片與 Live2D 小型驗證。可載入內容、輸出診斷；媒體與 Windows 方案有實測結論。
M1 垂直流程新遊戲、走動、拾取、換圖、購買、等待、NPC 事件、升階、存讀檔。同一路線可人工遊玩及自動通關。
M2 完整遊戲範本多角色、條件頁、標題／設定／背包／畫廊、多語與演出。兩位角色交錯推進；介面與跨存檔紀錄正確。
M3 發行與重用Windows 建置、解析度驗證、第二小型內容包、文件與測試報告。不改共用引擎即可替換遊戲內容；發行建置正常啟動。

示範遊戲內容

約 15–30 分鐘；1 位男主角、2 位女主角各 3 個連續事件；住處、室外、商店 3 張相連地圖；可拾取物、可啟動物與上鎖出口；購買、送禮及不足情境；地圖對話、背景立繪、CG、簡單動畫、影片各至少一例。可使用佔位素材。

MVP 驗收清單

  • 所有必要內容可用文字建立，無人工編輯器設定前置步驟。
  • 兩位女主角各自及交錯通關測試通過，條件頁與規則一致。
  • 資料驗證能抓出刻意注入的缺檔、懸空引用及缺譯。
  • 存讀檔完整還原單局狀態；設定、已讀與畫廊按規格跨存檔保存。
  • 三個時段、日數、NPC 配置與事件耗時運作一致。
  • 基本選單、影片結束／跳過、解析度與雙語驗證通過。
  • Windows 匯出產物可獨立執行，發行版無開發者入口。
  • 第二內容包不修改共用引擎；附資料說明、擴充範例與一鍵測試文件。
  • Live2D 有明確實測結論；若未通過，列出未交付能力並記錄範圍決策，不以靜態替代宣稱支援。
